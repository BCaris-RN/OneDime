## Rendered-page check
A Playwright script opened the pilot in Chromium for every skin in Light, Dark, System-with-OS-light and System-with-OS-dark, including explicit modes set opposite to the OS. It visited all four apps and the six First Dime sub-tabs plus Market > Selling, sampled every visible text element and placeholder, composited translucent backgrounds over their real parents, and compared unrounded ratios (3:1 for large text, 4.5:1 otherwise).
- Paper and Slate: 0 failures in any mode.
- Current: pre-existing failures, listed below and deliberately not changed.

## Palette adjustments
None of the supplied starting values were changed; every supplied pair passed. Added derived tokens where the brief needed values it didn't supply:
- Control boundaries (`--frame`, `--input-border`, `--chip-border`): the supplied `--border` values (#C9C4B6, #39445A, #BFC6CE, #3C434B) are under 3:1 against panels, so they are used only for decorative dividers. Inputs, chips and screen frames use darker or lighter boundary tokens that pass 3:1.
- D-pad in dark mode: first picks (#2B3548 Paper, #2A3036 Slate) measured 1.42 and 1.40 against the controller bar, so they became #64738F and #68727D (3.65 and 3.81).
- Slate light hover uses a dark overlay instead of white, because a white overlay on #8A5A00 would lower the white-text ratio.

## Exemptions (not counted as passes)
- Disabled buttons (55% opacity) are exempt under WCAG 1.4.3.
- Native control internals (select arrows, date-picker icons, radio and checkbox marks) are drawn by the browser. They follow `color-scheme` per mode and `accent-color` tokens but were not measured.
- Decorative dividers using `--border` carry no information.
- Shadows and the dialog backdrop are decorative.
